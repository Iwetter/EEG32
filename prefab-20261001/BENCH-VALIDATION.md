# Bench validation — all items pending measurement

Use an electrode simulator/phantom and the qualified FFC harness. No human connection is authorized by these tests. Record board serial, revision/hash, silicon lot/FICR, BOM substitutions, firmware build/register dump, battery/supply conditions, temperature, enclosure, instrument calibration/bandwidth, raw data and pass/fail reason. Set application noise, battery operating range, electrode model/offset range, range and fault-recovery requirements with the supervisor before declaring qualification. Proposed characterization sweeps below are test points, not established device specifications.

1. **+5VA ripple/noise with BLE active.** Measure TP9 against nearby GND and at each AFE supply, using a short ground spring/differential method. Capture DC accuracy, startup/overshoot, ripple peak-to-peak and spectrum with a stated 20 MHz limit and a separate acquisition-band analysis. Compare BLE off, connected idle, continuous notifications, RX and maximum configured TX power; vary battery, load and enclosure. Keep ADS1299 AVDD−AVSS within its 4.75–5.25 V operating range during valid acquisition. Correlate radio events with channel noise; allocate ripple/noise limits from the required EEG noise budget before signoff.

2. **Shorted-input ADS1299 noise.** Test each device's internal input short and an external CH-to-REF short through the actual input network/FFC, with a legal input common mode. Run 32 channels at 500 SPS, intended PGA gain/reference/filter settings, for at least ten minutes per BLE mode. Save raw codes; report input-referred RMS and peak-to-peak noise, PSD, 50/60 Hz interference, correlation and outliers. Compare internal-short results to TI's matching gain/data-rate noise conditions; account for external resistor/fixture noise. Do not compare mismatched bandwidths or claim a datasheet noise number without matching conditions.

3. **Regulator startup and low battery.** Within the approved battery/supply range, perform slow ramps, cold starts, power cycles and representative radio/acquisition load steps. Observe VBAT, +3V3, +5VA, enable/start/reset timing, input/output current and inductor waveform/temperature. Characterize dropout, boost startup, peak current, brownout, reverse/backfeed paths and data recovery. Identify the lowest usable VBAT with valid AFE rails, then define firmware shutdown/restart hysteresis. Compare biased C12/C13/C14 capacitance/ESR and L5 rolloff with ABLIC/Torex requirements. No battery chemistry/protection limits were supplied, so do not invent a discharge threshold.

4. **ADS1299 master/slave clock startup.** Probe TP5 AFE_CLK, TP6 START, resets, CS and DRDY with a logic analyzer/low-load probe. Read the master/slave clock-output/source configuration and all four ID/register sets. Verify U101's clock reaches U201/U301/U401 before START, correct nominal clock/data rate and synchronized frame numbering. Repeat at least 100 cold/warm/low-battery starts, including deliberate delayed reset/clock-enable sequences. Pass only with four valid devices, no hung startup and deterministic recovery; use TI's startup/reset timing requirements for the firmware sequence.

5. **BIAS stability.** With a phantom only, begin with a passive load and progressively vary electrode/contact resistance and cable capacitance. Suggested characterization points: 5/10/50/100 kΩ contacts and 100 pF/1 nF/10 nF load capacitance, including opens/one detached channel. Measure BIAS_DRIVE at TP8, remote BIAS after R634, settling, ringing, clipping and recovery during BLE activity. Verify 1 MΩ/1 nF feedback and the configured BIAS sense selections. Require no sustained oscillation over the specified load range; agree a settling/overshoot or measured loop-margin target before release. No compensation redesign is assumed.

6. **REF disconnect behavior.** Open/reconnect only the phantom REF conductor 33 while channels and BIAS remain connected. Record TP7, common mode, clipping/saturation, fault indications, recovery time and stale-data handling. Repeat intermittently and at offset/load corners. Define detectable bad-data criteria and inhibit/report invalid samples; acceptance requires a supervisor-approved recovery/fault response. Do not tie BIAS to REF to conceal this behavior.

7. **Electrode-offset headroom.** Use an isolated phantom source with controlled common mode to sweep differential DC offset and a small known AC signal through each CH/REF path. Test intended gains and supply/battery corners. Record clipping boundaries, gain, distortion, common-mode range, overload recovery and channel crosstalk. Compare to TI's differential full scale (reference/gain) and common-mode/PGA limits using actual register settings. Specify the electrode's worst-case offset before selecting a final gain; no offset requirement was supplied.

8. **32-channel, 500-SPS acquisition.** Apply distinguishable test tones or ADS internal test signals; verify CH01–CH32 order and all four status words. Capture CS/SCLK/DRDY and application frame timestamps for at least one hour. Demonstrate 500 complete synchronized frames/s, correct 24-bit sign conversion, no SPI overlap/partial frame and bounded latency. Each ADS frame contains 3 status +24 channel bytes; four devices produce **108 bytes/frame =54,000 bytes/s**, before application overhead. The channel-only payload is 48,000 bytes/s. Validate the actual firmware framing rather than assuming a transport configuration is adequate.

9. **BLE sustained throughput and dropped-frame detection.** Send the complete production payload at 500 SPS for at least one hour for each supported host and intended range, with coexistence/interference and battery corners. Include a monotonic frame sequence, acquisition timestamp, payload length and application integrity check; log queue high-water/overflow, notification acceptance, disconnects and host-side missing/duplicate/out-of-order frames. Test an intentionally throttled/disconnected receiver to prove detection and recovery. Compare produced/received frame counts and latency. Require no silent loss; target no drops in the defined normal environment, with any permitted loss/latency budget explicitly approved. BLE architecture is unchanged.

10. **HF crystal startup/frequency.** Read HFCLK source/status and verify the radio uses HFXO. Measure a buffered clock/test output or calibrated RF carrier; avoid loading the crystal pins with a normal probe. Repeat cold/warm starts across the crystal's specified −20…70°C range and approved VBAT range; log startup time/failures and frequency error against Nordic radio and ECS crystal limits. Record capacitor tolerance, PCB parasitics and reference instrument error. Also characterize LF crystal startup/timekeeping as a companion check. Do not alter loads/layout without evidence of a violated limit.

11. **Antenna return loss/range.** Use a calibrated/de-embedded VNA fixture to characterize the antenna/feed across 2.4–2.4835 GHz, bare and in the intended enclosure, with realistic phantom/body proximity and cable placement. Define the RF measurement plane and use a sacrificial/reworkable unit if temporary feed access is required; no permanent RF redesign is part of this checkpoint. Record S11/VSWR, resonance/bandwidth and BLE packet error/RSSI/throughput versus distance and orientation. A −10 dB S11 goal is a proposed engineering target, not a proven requirement; approve it and the required operating range. Run the applicable radiated-emissions test, including erratum-138-sensitive RX operation.

For every item, preserve the evidence and raise a concrete failed requirement before proposing a hardware change. The existing boost, input RC, BIAS compensation, crystal layout, antenna network, long analog routes and BLE architecture remain unchanged.
